# openwrt-tls-frag

**[English](README.md)**

باز کردن یوتیوب و اینستاگرام روی روتر OpenWrt، با تکه‌تکه کردن پیام TLS ClientHello
بین چند سگمنت TCP، به‌طوری که سیستم بازرسی هیچ‌وقت یک SNI کامل نبیند. بعد از آن
اتصال **مستقیم** به سرور اصلی برقرار می‌شود. نه سرور پروکسی، نه VPN، نه هزینهٔ
پهنای باند، نه چیزی که بابتش پول بدهید یا دسترسی‌اش را از دست بدهید.

این پروژه پیکربندی‌ای را بسته‌بندی می‌کند که از ۲۰۲۶-۰۸-۰۶ روی یک روتر خانگی
واقعی در حال کار است.

## تشکر و منبع

پارامترهای فرگمنت از
**[patterniha/Serverless-for-Iran](https://github.com/patterniha/Serverless-for-Iran)**
(با مجوز GPL-3.0) گرفته شده‌اند، از روی پیکربندی `Serverless-v48-low_delay` برای
v2rayN. همین مقادیر مشخص، تمام رمز کار هستند — این پروژه بدون آن کار وجود
نداشت. اگر این ابزار برایتان مفید بود، به آن مخزن ستاره بدهید.

کاری که این پروژه اضافه می‌کند بسته‌بندی است: نصب‌کننده برای OpenWrt، یکپارچگی با
Passwall2، حالت مستقل (transparent proxy)، و راستی‌آزمایی‌ای که واقعاً ثابت می‌کند
فرگمنتیشن دارد کار را انجام می‌دهد.

## محدودیت‌های واقعی — قبل از نصب بخوانید

- **فقط یوتیوب و اینستاگرام.** فهرست دامنهٔ ارسالی همین دو مورد را پوشش می‌دهد.
- **x.com کار نمی‌کند** با این روش. خارج از محدودهٔ این پروژه است.
- **جایگزین VPN نیست.** بقیهٔ ترافیک شما دست‌نخورده می‌ماند.
- **روی ISPهای ایران آزمایش شده**، با OpenWrt 25.12.5 aarch64 و Xray 26.7.28.
  پارامترهای فرگمنت برای رفتار یک سیستم بازرسی مشخص تنظیم شده‌اند. روی شبکه‌های
  دیگر ممکن است نیاز به تغییر داشته باشند — [docs/how-it-works.md](docs/how-it-works.md)
  را بخوانید تا بتوانید آگاهانه تغییرشان بدهید، نه با حدس و آزمون.
- **حالت مستقل نیاز دارد که کلاینت‌ها DNS را از طریق روتر حل کنند.** این حالت
  آزمایش و تأیید شده است (ببینید [docs/standalone-test-log.md](docs/standalone-test-log.md))،
  اما بر اساس آدرس IP هدایت می‌کند و فقط از روی پاسخ‌هایی که dnsmasq روتر می‌دهد
  یاد می‌گیرد کدام آدرس‌ها را هدایت کند. کلاینتی که از DoH/DoT مرورگر، DNS یک
  آداپتور VPN، یا یک DNS عمومی ثابت استفاده کند، کلاً از این مسیر خارج می‌شود.
  حالت Passwall2 این محدودیت را ندارد.

## پیش‌نیازها

| | |
|---|---|
| OpenWrt | نسخهٔ 22.03 به بالا (نیازمند fw4/nftables) |
| Xray-core | **≥ 26.6.27** — پایین‌تر از این، `finalmask` وجود ندارد و Xray بی‌صدا فرگمنت نمی‌کند |
| فضای آزاد rootfs | حدود ۲ مگابایت |
| حالت A | Passwall2، با یک نود **shunt** به‌عنوان نود سراسری |
| حالت B | `dnsmasq-full` (نسخهٔ ساده `dnsmasq` پشتیبانی `nftset` ندارد) |

‏Xray همراه پروژه نمی‌آید. اول نصبش کنید: `apk add xray-core` (یا
`opkg install xray-core`).

## نصب

```sh
git clone https://github.com/<you>/openwrt-tls-frag
cd openwrt-tls-frag
./install.sh
```

دستور `./install.sh` به‌صورت خودکار تشخیص می‌دهد: اگر Passwall2 نصب باشد از آن
استفاده می‌کند، وگرنه حالت مستقل. برای انتخاب دستی:

```sh
./install.sh --mode passwall2
./install.sh --mode standalone
```

گزینه‌ها:

| سوییچ | کارکرد |
|---|---|
| `--mode auto\|passwall2\|standalone` | پیش‌فرض `auto` |
| `--scope-ip <ip>` | فقط حالت مستقل — اعمال قوانین روی یک IP مبدأ. برای تست ایزوله. |
| `--no-verify` | رد کردن بررسی پس از نصب (توصیه نمی‌شود) |
| `--no-stats` | نصب نکردن نمونه‌بردار آمار یک‌دقیقه‌ای |

### حالت A — ‏Passwall2

یک نود SOCKS به نام `FRAGDRCT` اضافه می‌کند که به فرگمنتر اشاره دارد، یک قانون
shunt به نام `FragTCP` که دامنه‌های یوتیوب/اینستاگرام را به آن می‌فرستد، و یک
قانون `FragUDP` که QUIC آن‌ها را بلک‌هول می‌کند تا مرورگر مجبور شود به مسیر TCP
برگردد — همان مسیری که فرگمنت می‌شود.

شناسهٔ نود shunt سراسری **کشف می‌شود** و هرگز ثابت نوشته نشده است — این شناسه در
هر نصب تصادفی است. اگر نود سراسری شما shunt نباشد، نصب‌کننده به آن دست نمی‌زند و
همین را به شما اطلاع می‌دهد، به‌جای اینکه مسیریابی‌تان را خراب کند.

### حالت B — مستقل

برای روترهایی که هیچ بستهٔ پروکسی ندارند. ‏dnsmasq دامنه‌های هدف را حل می‌کند و
داخل یک set در nftables می‌ریزد؛ ‏fw4 ترافیک TCP منطبق را به ورودی
`dokodemo-door` هدایت می‌کند و QUIC منطبق را دور می‌ریزد. اول محدودیت DNS بالا را
بخوانید.

## راستی‌آزمایی

نصب‌کننده صرفاً به این دلیل که «پروسه بالا آمد» موفقیت اعلام نمی‌کند. چنین بررسی‌ای
برای یک پیکربندی که هیچ کاری نمی‌کرد هم موفق می‌شد — و این دقیقاً همان خطای مثبت
کاذبی است که در جریان توسعه رخ داد، جایی که ترافیک بی‌سروصدا از روی یک VPN
می‌رفت.

به‌جای آن یک بررسی **تفاضلی** انجام می‌دهد. یک Xray موقت روی یک پورت جداگانه بالا
می‌آورد با همان resolver DoH و همان `sockopt.mark 255`، ولی بدون مرحله‌های
فرگمنت، و مقایسه می‌کند:

```
verify: control https://www.google.com unfragmented = 200 OK
verify: https://www.youtube.com  fragmented=200  unfragmented=000  OK
verify: https://www.instagram.com  fragmented=200  unfragmented=000  OK
verify: PASS - fragmentation is doing the work
```

فقط وقتی قبول می‌کند که سایت‌های هدف **از طریق** فرگمنتر کار کنند **و** روی همان
مسیر بدون آن شکست بخورند. اگر بدون آن هم کار کنند، به شما گفته می‌شود که این نصب
هیچ چیزی را ثابت نمی‌کند — یا خط شما آن‌ها را مسدود نمی‌کند، یا چیز دیگری دارد
ترافیک را حمل می‌کند.

توجه کنید که `curl --noproxy` در اینجا کنترل معتبری **نیست**: این گزینه فقط
پروکسی مبتنی بر متغیرهای محیطی curl را غیرفعال می‌کند، نه رهگیری شفاف nftables
را. روی یک روتر با Passwall2، یک درخواست «مستقیم» به youtube.com کد ۲۰۰ برمی‌گرداند
در حالی که از روی VPN رفته است.

## حذف نصب

```sh
./uninstall.sh
```

سرویس را متوقف و غیرفعال می‌کند، `/etc/xray-frag`، `/etc/init.d/xray-frag`،
`/usr/bin/xray-frag-stats`، خط cron و هر قانون فایروال/dnsmasq مربوط به حالت
مستقل را حذف می‌کند. نسخهٔ پشتیبان زمان‌دار `/etc/config/passwall2` را که هنگام
نصب گرفته شده بازمی‌گرداند، و سپس بخش‌های UCI این پروژه را در هر حالت پاک می‌کند —
یعنی «حذف شد» واقعاً یعنی حذف شد، حتی اگر روتر قبلاً دستی پیکربندی شده بوده باشد.

## پایش منابع

```sh
xray-frag-stats now      # حافظه، ترد، پردازنده، اتصال‌های باز
xray-frag-stats history  # اوج مصرف و ۲۰ نمونهٔ آخر
xray-frag-stats watch    # زنده
```

تاریخچه **عمداً** در `/tmp` (‏tmpfs) نگهداری می‌شود: بدون نوشتن روی دیسک، بدون
فرسودگی حافظهٔ فلش. با ری‌بوت پاک می‌شود و این معاملهٔ پذیرفته‌شده است — دستگاه
مرجع فقط حدود ۳۶ مگابایت فضای آزاد روی rootfs دارد.

## هزینهٔ منابع

حافظهٔ RSS حدود ۳۶ تا ۴۲ مگابایت، ثابت در ۳۰ اتصال هم‌زمان (بدون نشتی). ۸ ترد.
حدود ۱ تا ۲ درصد میانگین یک هستهٔ پردازنده. حدود ۳۲ میلی‌ثانیه CPU برای هر
دست‌دادن TLS.

هزینه با **تعداد اتصال بر ثانیه** بالا می‌رود، نه با پهنای باند:
`packets: "tlshello"` فقط دست‌دادن اولیه و `packets: "1-1"` فقط اولین نوشتن را
فرگمنت می‌کند، پس سرعت انتقال دست‌نخورده می‌ماند. برای مقایسه، روی همان دستگاه
‏Xray خودِ Passwall2 حدود ۸۰ مگابایت و sing-box آن حدود ۴۲ مگابایت مصرف می‌کند.
